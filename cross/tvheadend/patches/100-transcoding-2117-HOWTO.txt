Patches 101 and 103 are ours on top of this one, not (yet) in his branch, each
generated from its own commit on a local branch over his:

  101  make the FF_AV_PROFILE_UNKNOWN default reach an existing installation:
       the default is assigned before idnode_load(), which then overwrites it
       from the saved config -- and every saved codec profile holds
       "profile": 0, so the default never applies to an installed profile.
       For aac that re-creates the "Profile not supported!" failure the old
       "profile > 0" test was masking; for nvenc it imposes Baseline.  Adds
       config_migrate_v26 to rewrite the stored zeros, and drops the two aac
       profiles the native encoder cannot open.  Full analysis in the patch
       header; offered to uknunknown for #2117, drop it once it is upstream.

(the numbers below are the older, now dropped, set)

  101  keep the QSV scaler width even
  102  ship 360 rather than 384 as the default profile height: 16:9 does not
       divide into 384, so each path rounds the width its own way, while 360 is
       a whole 640 for 16:9 and 480 for 4:3 (a fresh install only)
  104  give the output component the geometry the filters produce: the muxer
       writes the component's size into the container, so a WebM VP8 track
       announced 1920x1080 while its frames were 640x360 (H264/HEVC/VP9 hide
       it, their bitstreams carry the size)
  103  a watchdog for an encoder that stops returning: a GPU reset leaves the
       QSV/VAAPI call inside the driver, where the consecutive-error counter
       cannot see it.  It cannot free the stuck thread -- nothing in the process
       can -- but it names the cause in the log and arms that counter, so the
       stream dies as soon as the driver returns

101 in detail:
vpp_qsv rejects w=-2, so the QSV scale filter asked for w=-1, which rounds to
the nearest width and can land on an odd one -- 1280x720 scaled to h=384 gives
683 where the encoder uses the profile's even 682.  On Apollolake that hung the
media engine (i915 "Hang on vcs0" in the sharer thread, encoding hevc_qsv) and
wedged tvheadend until it was stopped.  Drop 101 once it is upstream.

Verify a regenerated patch reproduces the branch exactly rather than trusting
`patch --dry-run`: a patch whose change is already present can still apply with
fuzz and duplicate the block. Extract the tarball, apply, and diff against
`git archive <head>`; it should report no differences at all.

# Regenerate the patch from the working tree. The base MUST equal the
# cross/tvheadend Makefile PKG_GIT_HASH (the distrib tarball the patch applies to),
# otherwise upstream commits between the old base and the new base leak into the
# patch and show up as "Reversed (or previously applied) patch detected".

HASH=$(sed -n 's/^PKG_GIT_HASH = //p' ../Makefile)   # current distrib base
cd <tvheadend git worktree>
git diff --no-prefix ${HASH}..HEAD > \
    <spksrc>/cross/tvheadend/patches/100-transcoding-2117.patch

Alternative directly from the github PR:
curl -L https://github.com/tvheadend/tvheadend/pull/2117.patch \
| perl -0777 -pe '
    s/^diff --git a\/Makefile\.ffmpeg.*?(?=^diff --git )//ms;
    s/^--- a\//--- /mg;
    s/^\+\+\+ b\//+++ /mg;
' \
> 100-transcoding-2117.patch

Alternate using sed breaks on no newline entries
curl -L https://github.com/tvheadend/tvheadend/pull/2117.patch \
    | sed '/^diff --git a\/Makefile\.ffmpeg/,/^diff --git /{//!d;/^diff --git a\/Makefile\.ffmpeg/d}' \
    | sed '/Makefile\.ffmpeg/d' \
    | sed -e 's?--- a/?--- ?1' \
          -e 's?+++ b/?+++ ?1' \
    > 100-transcoding-2117.patch
